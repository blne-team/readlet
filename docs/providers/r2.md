# The Cloudflare R2 provider

Managers can add EPUBs and PDFs directly from `/manage`, either by uploading a
file or pasting a public HTTPS file URL. Readlet streams the file into the
bound R2 bucket and updates the catalog after import. The limit is 100 MB per
file. `pnpm sync` contributes its local folder without replacing books imported
through the browser.

Sync uploads also pass through the Worker, so each individual book or cover
must fit the deployment's [Worker request body limit](https://developers.cloudflare.com/workers/platform/limits/#request-limits).

Cloudflare R2 keeps your library in a bucket served by a Worker. Both browser
imports and `pnpm sync` publish through the Worker's R2 binding.

## Setting it up

You'll need a Cloudflare account.

**1. Edit the deployment and publishing settings.** Both files are checked in
with example values and are meant to be changed:

| file | change |
| --- | --- |
| `readlet.config.json` | Set `storage.endpoint` to `https://<your-readlet-host>/api/library/sync` |
| `apps/readlet/wrangler.jsonc` | Set `name`, the `r2_buckets` bucket name and jurisdiction, and `READLET_R2_BILLING_DAY` to the UTC day when your Cloudflare billing period begins |

The Worker endpoint writes through its `BOOKS` binding, so the bucket and its
optional jurisdiction are configured only in `wrangler.jsonc`.

**2. Log in and deploy:** Before the first deploy, keep `workers_dev`
and `preview_urls` set to `false` in `apps/readlet/wrangler.jsonc` and do not
configure a route or custom domain. This keeps the Worker private until Access
is ready.

```bash
pnpm --filter @readlet/app exec wrangler login
pnpm run deploy
```

If you use an API token instead of `wrangler login`, keep it outside the
repository's `.env` files. OpenNext packages values from those files into the
Worker. Put `CLOUDFLARE_API_TOKEN=...` in an ignored `.wrangler-auth` file at
the repository root, then run commands with Node's environment-file option:

```bash
node --env-file=.wrangler-auth "$(command -v pnpm)" run deploy
```

The deploy script checks the generated Worker environment before upload.
If an earlier Worker version was built while the token lived in `.env`, roll
that token in **My Profile → API Tokens** and replace `.wrangler-auth` with the
new value. Older Worker versions keep their bundled code.

**3. Protect the Worker with Cloudflare Access, then give it a public URL.**
Deploying alone does not enable authentication. Follow
[Protect the Worker with Cloudflare Access](#protect-the-worker-with-cloudflare-access)
before adding a public hostname.

**4. Give sync its own credentials, then publish.** Create a Cloudflare Access
service token and add a Service Auth policy for it to the Worker's Access
application. Copy the tracked template and put the service token credentials in
the ignored `.env.sync` file:

```bash
cp .env.sync.example .env.sync
```

```bash
node --env-file=.env.sync "$(command -v pnpm)" sync
```

The service token gets each sync request through Access. It belongs only in
`.env.sync`, not in a normal Next.js `.env` file.

## Protect the Worker with Cloudflare Access

This setup protects the deployed Worker, including its shelf, OPDS feed, covers,
downloads, API routes, and static assets. It does not protect `pnpm dev`,
`pnpm preview`, or a separate Node or Docker deployment. Cloudflare authenticates
the request before the Worker runs; Readlet then authorizes the verified
identity against its own user directory.

1. In the Cloudflare dashboard, enable Zero Trust for your account if needed.
   Under **Zero Trust → Integrations → Identity providers**, add **One-time PIN**
   if it is not already available.
2. Go to **Workers & Pages → your Readlet Worker → Access → Protect this Worker
   behind Access**. Choose **All traffic**, including production and previews.
   In the Access application's **Authentication** settings, enable the identity
   provider readers will use. An **Allow** policy may admit that login method or
   a broader organization group because reaching the Worker is not sufficient:
   every private Readlet route also requires an active internal user. Do not use
   a **Bypass** policy, which supplies no verified identity.
3. Check **Zero Trust → Access controls → Applications** for any hostname or
   path policy matching your shelf URL. A matching hostname/path policy takes
   precedence over the Worker policy; remove or tighten any rule that would
   admit more people. In **R2 → your bucket → Settings**, confirm **Public
   Development URL** is disabled and no **Custom Domain** serves the bucket
   directly. Access on the Worker cannot protect a separate bucket URL.
4. Only after Access is active, add the public hostname under **Workers & Pages
   → your Readlet Worker → Settings → Domains & Routes**. Use a custom domain,
   route, or enable the Worker's `workers.dev` URL. If you enable `workers.dev`,
   also change `workers_dev` in `apps/readlet/wrangler.jsonc` so the next deploy
   does not turn it off again. The Worker-level Access policy covers each of
   these URLs.
5. Set the three runtime variables below, then open the shelf in a private
   browser window as the bootstrap manager. A different authenticated address
   must see Readlet's denial page. Before configuring OPDS app passwords,
   requests without an Access session must not expose a feed, cover, download,
   or state API. Check every public hostname bound to the Worker.

### Configure identity and the first manager

Set these runtime variables on the Worker under **Settings → Variables and
Secrets**:

| variable | value |
| --- | --- |
| `READLET_ACCESS_TEAM_DOMAIN` | `https://<your-team>.cloudflareaccess.com` |
| `READLET_ACCESS_AUD` | the Application Audience (AUD) Tag from **Zero Trust → Access controls → Applications → your application → Additional settings** |
| `READLET_BOOTSTRAP_MANAGER_EMAIL` | the verified email that owns this library |

The repository-root `.env` is not Worker runtime configuration. For local Next
development or a Worker preview, copy
`apps/readlet/.env.example` to `apps/readlet/.env.local` and fill it in. For a
deployed Worker, set the values in its runtime settings; a local file and
`pnpm build` do not publish them. Restart local servers after changing the file.

Readlet verifies the signed application token on every private request. If the
user directory is empty, only the configured email may create it; that first
user becomes a manager. Managers invite other verified emails at `/users`.
Each invitation binds permanently to the Cloudflare user `sub` on first login
and owns a stable, private reading-state key.

There is no unauthenticated or manual-profile mode. A local request without a
real Access application token is denied, so exercise the authenticated app
through its protected hostname.

This deployment has `workers_dev` on after Access was configured, while
`preview_urls` remains off. Worker-level Access covers both if you enable
preview URLs later. For a dedicated reader, create path-specific bypass
applications for `/opds`, `/opds/*`, `/cover/*`, and `/download/*`; Readlet
then requires the app password generated on its Users page. Do not bypass any
of those paths until an OPDS password exists. See
[the OPDS guide](../opds.md#access-and-opds-clients).

Cloudflare documents [Worker-level Access](https://developers.cloudflare.com/workers/configuration/cloudflare-access/),
[One-time PIN setup](https://developers.cloudflare.com/cloudflare-one/integrations/identity-providers/one-time-pin/),
and [R2 public access](https://developers.cloudflare.com/r2/buckets/public-buckets/).

## Configuration

```json
{
  "storage": {
    "provider": "r2",
    "endpoint": "https://readlet.example.com/api/library/sync"
  }
}
```

| key | what it does |
| --- | --- |
| `endpoint` | the deployed Readlet `/api/library/sync` endpoint |

## R2 free-tier safety budget

Readlet reserves every R2 operation before issuing it. The shared Durable
Object ledger stops Class A operations at 800,000, Class B operations at
8,000,000, and conservatively reserved storage at 8 GB. These are 80% of the
R2 Standard monthly free allowances. Failed and retried operations stay
reserved; overwriting an object never reduces its reserved size. This bias can
stop the library early, but cannot make it spend past its recorded cap.

Managers can see the current period and all three meters at `/resources`. Warning
and critical states begin at 60% and 70% of the underlying free tier. Operation
counters reset on `READLET_R2_BILLING_DAY`; reserved storage carries forward.

Managers can delete books from `/manage`. Readlet first removes the book from
the catalog, then finishes deleting its metadata, cover, formats, reading
positions, and annotations in the Worker's background task. The management
page shows the book under **Finishing deletion** and refreshes briefly while
cleanup runs. If the background task is interrupted, its private cleanup record
remains and **Finish deletion** retries it. The browser never receives or
submits arbitrary bucket keys.

The ledger covers the Worker and `pnpm sync`, because both use the Worker's R2
binding. Keep the bucket's public URL and
custom domains disabled, do not modify it from the dashboard or another client,
and do not share the account's R2 free allowance with an untracked application.
Those paths do not pass through Readlet and therefore cannot be stopped by its
ledger. Use R2 Standard: Infrequent Access has no free tier.

The first deployment starts a new ledger; it cannot reconstruct operations
already spent in the current period. For a strict first cycle, deploy at the
start of the configured billing period and immediately run a full sync so every
library object has a storage reservation.

## Testing locally

Use the filesystem provider with `pnpm dev:no-auth` for interactive local
development. R2 sync deliberately targets the deployed, Access-protected
Worker.

## Troubleshooting

**Your shelf is empty after deploying.** You may have deployed before
publishing. Confirm that `storage.endpoint` reaches this Worker, check its
`BOOKS` binding, and run `pnpm sync`.

**`no binding named BOOKS`.** The Worker has no R2 binding. Check the
`r2_buckets` entry in `apps/readlet/wrangler.jsonc`.

**You want your shelf off the public internet.** Set `workers_dev` to `false`
in `wrangler.jsonc` and redeploy to disable the `*.workers.dev` URL. Remove
any other public routes or domains too. Turning on a URL does not enable Access
by itself.
